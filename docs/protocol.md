# SolidLink protocol baseline

The protocol source of truth is [`core/protocol/src/main/proto/solidlink.proto`](../core/protocol/src/main/proto/solidlink.proto). It uses proto3, a single `Envelope.oneof` for control/data dispatch, explicit optional presence where unset differs from a default, and reserved tags for removed fields.

The stream is a sequence of official Protobuf delimited messages: the generated runtime writes a message-size varint followed by the serialized message. `ProtobufStreamCodec` uses the official generated runtime and `CodedInputStream` with a negotiated maximum envelope size. It never introduces magic bytes, a second manual length prefix, JSON, or base64 file payloads.

`Chunk.payload` is bounded and the default codec ceiling is 1 MiB for the serialized envelope. A chunk fixture leaves room for envelope metadata and remains below that ceiling. Larger files must be represented as multiple chunks; they are never loaded as one message.

The receiver rejects missing-body envelopes, declared sizes above the negotiated limit, malformed input, and truncated messages with typed `ProtocolCodecException` codes. A stateful `ProtobufStreamReader` must be used for sequential messages on one input stream so generated-runtime buffering is preserved correctly.

## Verification

The protocol module currently has five codec tests and one golden-vector test. The golden vector is generated by the official runtime and stored at `core/protocol/src/test/resources/golden/hello_envelope.delimited.bin`; the normal test suite compares regenerated bytes against it.

The Android build commands are:

```text
./gradlew :core:protocol:test
./gradlew :core:protocol:jar
```

Cross-platform SwiftProtobuf generation and parity tests are deliberately deferred to the iPhone companion phase. The committed `.proto` file remains the shared contract.
